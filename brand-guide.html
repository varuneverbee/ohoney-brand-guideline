Ohoney Brand Guide

This guide contains the approved Ohoney logo, icon, color variants, usage rules, and production-ready files. Use these assets consistently across product, marketing, presentations, social media, and partner materials.

Browse the library
Every file here is generated from one source. The mark's outlines and the wordmark's letterforms live in apps/web/src/shared/ui/logo-geometry.json in the Ohoney app repository. Never hand-edit an exported file — it will be overwritten on the next regeneration.

02 — Logo system

Two parts, one system

The identity is a honey dipper mark and the Ohoney wordmark. Both are a single SVG: the wordmark is outlined letterforms, not live text, so it renders identically everywhere and needs no font to load.

#fdfaf3

Primary lockup

The default logo. Use it for website headers, landing pages, presentations, marketing and social graphics, partner pages, and product communication.
Files: SVG (light, dark, single-color).

#fdfaf3

Standalone icon

The mark alone. Use it for favicons, app icons, avatars, social profile images, compact navigation, and anywhere the wordmark would fall below its minimum size.
Files: SVG (brand, single-color), PNG 16–512.

04 — Clear space

Keep the logo uncrowded

The measuring unit is x, the height of the capital O. In the lockup the O is 60.6% of the logo's full height, so at a 24 px logo, x = 14.6 px.

Preferred: 1x on all four sides. Minimum: 0.5x. Nothing else may enter that area — no type, rules, buttons, image edges, or other logos.

 Protected area x = 0.606 × logo height

Correct  1x of clear space on every side.

PricingSign in

Incorrect  Neighbouring content sits inside the protected area.

The standalone icon uses the same rule measured against its own height: 1x preferred, 0.5x minimum, where x is the icon's height. Favicons and app icons are exempt — the platform controls that padding, and the exported files already carry it.

Below 64 px wide, drop the wordmark and use the standalone icon. Shrinking the lockup further doesn't fail gracefully — the honey letterforms close up before the mark does.
Print values are derived, not press-proofed. 25 mm and 6 mm are conservative floors that keep the dipper's three ridges from filling in under ink spread. Pull a proof on the actual stock before committing to anything smaller.

09 — Favicons & app icons

Small sizes

Favicons use the standalone mark — never the wordmark, which falls below its minimum size long before 32 px. Tab icons are transparent so they sit on the browser's own chrome; installed app icons keep an opaque tile.

SVG first, .ico only where required. Every modern browser accepts favicon.svg via <link rel="icon" type="image/svg+xml"> — that's what actually serves the tab. favicon.ico exists purely as the fallback the format still requires for very old browsers, bookmarklets, and OS-level shortcut caching that won't read SVG. Don't reach for .ico anywhere else; the app icons below are PNG because iOS and the web app manifest mandate raster, not because .ico was ever an option there.
Why app icons keep their tile. A transparent PNG is composited unpredictably by iOS, and is invalid as an Android maskable icon. So these sit on an opaque #20170d tile at 6.4 : 1. The maskable file is full-bleed square — the platform applies its own mask, and baked-in corners would double up. The 192 and 512 files are the two referenced by the web app manifest; 180 is Apple's.

10 — Asset library

Approved files

Fourteen approved files. Every one downloads directly from this page.

There are no PNG exports of the lockup, by design. The lockup ships as SVG only — it is resolution-independent and carries no font dependency, so a raster would only ever be worse. If a partner platform can't take SVG, ask an engineer to add the size you need to the asset generator so it stays generated from the same source rather than exported by hand.

11 — Developer usage

In the codebase

Inside the Ohoney web app, never reference an SVG file or hand-roll a lockup. Import the shared component — it is the single implementation, and it keeps the mark, the outlined wordmark, and the accessibility contract in one place. 

// apps/web/src/shared/ui/logo.tsx
import { Logo, LogoIcon, LOGO_ICON_URL } from '@/shared/ui/logo'
PropTypeDefaultNotes
variant'light' | 'dark' | 'auto''auto'Ground the logo sits on. auto inherits the surface's text color for the O; prefer an explicit variant on a dark surface, since auto can't adapt the gradient.
type'full' | 'icon''full'full is mark + wordmark; icon is the mark alone.
size'sm' | 'md' | 'lg''md'Heights, not font sizes — 16 / 20 / 24 px. The lockup scales as one unit.
classNamestring—Merged onto the root <svg>.
titlestring—Required when the logo is the only content of a link or button — the wordmark is paths, so without it there is nothing to announce.

Examples

// Light surface — marketing header, app sidebar
<Logo variant="light" size="lg" />

// Dark surface — the closing CTA band, a dark footer
<Logo variant="dark" size="lg" />

// Mark alone — compact nav, avatar, tight space
<Logo type="icon" size="md" />

// Accessible: the logo IS the link, so it must be labelled
<Link to="/">
  <Logo variant="light" title="Ohoney home" />
</Link>

// Decorative — a heading nearby already names the brand.
// Omit `title` and it is marked aria-hidden for you.
<Logo variant="light" />

// Responsive: full lockup from sm up, mark alone below —
// the wordmark's 64px floor, enforced in layout
<Logo type="icon" className="sm:hidden" />
<Logo variant="light" className="hidden sm:block" />

// Only where a logo is held as data beside third-party URLs
// (model picker, connection cards). Prefer the component.
{ logo: LOGO_ICON_URL }

Outside the SPA

For emails, docs, slides, or a partner's site, link the standalone SVGs rather than recreating the lockup.

<link rel="icon" type="image/svg+xml" href="/assets/brand/favicon.svg" />
<link rel="icon" sizes="16x16 32x32 48x48" href="/assets/brand/favicon.ico" />
<link rel="apple-touch-icon" sizes="180x180" href="/assets/brand/apple-touch-icon.png" />
